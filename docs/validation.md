Дата: 2026-10-18. Проверка выполнена в существующей подготовленной рабочей
копии, после реорганизации медиа и обновления документации.

  `c05f8d6d608afd588469b7a8ef0929d5a1f8f6bb`, восстановленная из метаданных
  15 файлов локального кеша; их SHA256 записаны в `source-model.sha256`.
- TensorFlow Lite source v2.18.0,
  `6550e4bd80223cdb8be6c3afd1f81e86a4d433c3`.
- PocketFFT `c90e55b3d529f8efa40ed01a20de22405f45fc65`.
- GCC 13.3, CMake 3.28.3, FFmpeg 6.1.1.

## Сжатие и декодирование

На первых трёх секундах локального `media/client_android/demo.mp3`:

- Python batch encoder на CPU: один успешный трек, ноль ошибок,
  `container_validated: true`.
- SST: 6112 bytes, 75 codec frames, 3 chunks, CRC status OK.
- Контрольный WAV Python: PCM16, 48000 Hz, stereo, 144000 PCM frames,
  576044 bytes.
- Независимый C++ CLI прочитал записанный SST и создал WAV с тем же
  форматом, длиной и размером. Это проверка структуры/длины, не качества
  звука и не побитового совпадения WAV между реализациями.

Все шесть Bash-блоков из [roundtrip.md](roundtrip.md) извлечены из Markdown
и успешно выполнены как один сценарий с локальным демофайлом
и `--max-seconds 3`. Проверены также чтение catalog, проверки WAV и ffprobe.
Логи и файлы экспериментов находятся в исключённом из Git
`media/docs-smoke/`; эти пути являются локальными свидетельствами,
а не обязательными входами документации.

## Экспорт моделей

Рецепт из [model-export.md](model-export.md) выполнен в новом каталоге:
codebooks → динамический SavedModel → фиксированный f25 SavedModel →
FP32/FP16 builtin-only core и окно iSTFT.

Экспортёр завершился с кодом 0 и `FP32 validation PASSED`.
Для этого прогона FP32 audio RMSE относительно полного TensorFlow decoder:
`8.040e-07`, SNR `103.32 dB`; FP16 audio RMSE `1.073e-04`, SNR `60.81 dB`.
Это численная проверка экспортёра на его тестовых embeddings, а не
оценка качества кодирования музыки. Повторный экспорт не обязан иметь
те же байты TFLite, что переданный исходный набор.

Новая FP32-модель, новые codebooks и окно также проверены через
`test_c_api` на коротком SST. Все его проверки прошли: создание/удаление,
обычное и повторное декодирование, информация потока, отмена и ошибки API.
Большие промежуточные SavedModels и повторно экспортированные веса после
проверки удаляются; лог и JSON-отчёт сохраняются в `media/docs-smoke/`.

## Сборка и тесты

- Пересобраны C++ CLI и тестовые цели с имеющимися локальными зависимостями.
- `sst_reader`, `rvq_dequantizer`, `istft` проходят через CTest.
  Для iSTFT исправлен рабочий каталог CTest: тест читает окно из `models/`
  относительно `decoder_cpp/`, как и остальные тесты assets.
- Полный CTest с многократным декодированием исходной 162-секундной фикстуры
  в `c_api` не повторялся; вместо него проверен C API на 3-секундном SST.
- `flutter analyze --no-pub` прошёл без замечаний.
- Widget-тест прошёл после `flutter pub get --offline` на Flutter 3.44.8 /
  Dart 3.12.2. До обновления generated package config использовались пути
  прежнего Flutter SDK, что вызывало ошибку компиляции внутри Flutter.
  Новый SDK временно обновил пять SDK-зависимостей; исходный `pubspec.lock`
  восстановлен, обновление зависимостей не включено в изменение документации.

## Что этой проверкой не подтверждено

Свежая установка Python-окружения и загрузка весов/исходников из сети
с чистого клона не повторялись. Ревизии и команды для этого записаны
в [setup.md](setup.md), контрольные суммы локальных исходных весов и
основного набора runtime проверены.

GPU-кодирование, новый Android APK, реальное воспроизведение на устройстве,
длительные нагрузочные тесты и метрики качества аудио в этот прогон не входили.
Widget-тест не подтверждает работу FFI и аудиовывода. Полнота поставки
Gradle Wrapper для чистого клона отмечена в
[README клиента](../client_android/README.md).

Измерения времени короткого прогона выполнялись параллельно со сборкой;
их нельзя считать надёжным сравнительным бенчмарком.
