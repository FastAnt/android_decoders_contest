# Android benchmark data

This directory contains the raw values and the plotting script for
[../performance.md](../performance.md).

## Files

- `measurements.json` — device metadata, codec payloads, SpectroStream
  full-track/thread/core results, SAGE results, and app-level observations.
- `plot_benchmarks.py` — regenerates the PNG figures in `../images/`.

## Device and software

- AAOS on Tangorpro, Google Tensor G2 (`GS201`), 8 CPU cores, 7.6 GB RAM.
- Android 15 / API 35, arm64-v8a.
- Flutter debug app; TFLite 2.18 + XNNPACK for SpectroStream; LiteRT 2.3.0
  for SAGE.
- Demo: generated track, 133.6 s, 48 kHz stereo.

## SpectroStream CLI procedure

The local models and Android CLI are not in Git. Build them as described in
[../../decoder_cpp/README.md](../../decoder_cpp/README.md), then:

```bash
adb shell mkdir -p /data/local/tmp/sscbench
adb push decoder_cpp/build-android-arm64-v8a/spectrostream_decode \
  /data/local/tmp/sscbench/
adb push client_android/android/app/src/main/jniLibs/arm64-v8a/libc++_shared.so \
  /data/local/tmp/sscbench/
adb push decoder_cpp/models/spectrostream_decoder_core_fp32_f25.tflite \
  decoder_cpp/models/rvq_codebooks.f32 \
  decoder_cpp/models/istft_window_f960.f32 \
  client_android/assets/spectrostream/demo.sst \
  /data/local/tmp/sscbench/
adb shell chmod +x /data/local/tmp/sscbench/spectrostream_decode

adb shell 'cd /data/local/tmp/sscbench && LD_LIBRARY_PATH=. ./spectrostream_decode \
  --model spectrostream_decoder_core_fp32_f25.tflite \
  --codebooks rvq_codebooks.f32 \
  --window istft_window_f960.f32 \
  --input demo.sst --output out.wav --threads 6 --cores 8'
```

The 30 s scaling runs used a short excerpt encoded with
`encoder_service/batch_encode.py`; the full-track run used the checked-in
`demo.sst`. `--threads N --cores M` maps directly to the runtime controls.

## SAGE procedure

The SAGE values were taken from the standalone SAGE benchmark on the same
device and are recorded in
`sage_android_results.json` in this directory. They are not generated by
this repository's app. The relevant values are copied into
`measurements.json` with their source noted.

## App procedure

The app observations come from a single run per mode on the debug build:

- launch the app, select the mode in Settings, apply;
- tap Play and wait for `STREAMING`;
- open HISTORY and read the recorded time;
- read process PSS with `adb shell dumpsys meminfo com.neuralcodecs.client_android`.

The MP3 player did not reach playback during that session, so no MP3 startup
value is included. The checked-in MP3 size and bitrate are still measured
directly from the asset.

## Regenerate figures

```bash
uv run --with matplotlib python docs/benchmarks/plot_benchmarks.py
```

The script writes PNGs into `docs/images/` and requires only Python 3 and
matplotlib.
